## 2. What works

Public API (`src/index.ts:1-166`) [inspected]: a module-singleton `SandboxManager` with `initialize(config, askCallback?, enableLogMonitor?, options?)`, `wrapWithSandbox(command, binShell?, customConfig?, abort?, options?)`, which returns a shell string on POSIX, `wrapWithSandboxArgv(...)`, which returns `{argv, env}` and is the only method that works on Windows, plus `checkDependencies()`, `updateConfig()`, `reset()`, `registerCommandNetworkLists()`, violation-store accessors, zod schemas, and roughly 40 Windows install and status functions. There is also a CLI (`src/cli.ts`) and a standalone proxy, `srt proxy`, driven by an external decider (`docs/srt-proxy.md`).

## 4. Architecture

Control flow: `initialize(config)` (`sandbox-manager.ts:1099-1195`) resolves the parent proxy, the address guard and the optional MITM CA, then runs `checkDependenciesAsync()` and throws on any error (1176-1195). It then starts the proxies. On Windows it verifies the srt-win install version, applies persistent ACL grants and probes the WFP fence under the write-restricted token. If the probe is not blocked, initialization fails (`windows-sandbox-utils.ts:1665-1712`; `README.md:780, 821`). `wrapWithSandbox` and `wrapWithSandboxArgv` compute read/write/credential/network restrictions per call, optionally overridden by `customConfig` (2439-2778), and dispatch to the platform wrapper. An unknown platform throws (2772-2776).

State is module-global (`sandbox-manager.ts:167-190`): one configuration, one proxy pair and one CA per Node process. Per-command variation comes through `customConfig` and per-command network allow lists. The README says those lists are "attribution, not a boundary between concurrent commands" (`README.md:381`).

Lifecycle: `reset()` stops the proxies and releases per-session ACLs. Windows write grants on `allowWrite` roots persist across sessions by design (`README.md:811-817`). A Windows child dies when its broker dies (`srt-win exec --held-by`, exit 26; `README.md:934`). On Linux the child dies with bwrap (`--die-with-parent`).

Identity: no principal model. The OS identity is the caller's uid on POSIX and `srt-sandbox` on Windows. Proxy connections are attributed by a per-session token plus the commandId in the proxy username.

Secret reflection (S-1), settled from the code at c40cf14a [inspected; the leak itself not executed]:

1. In env-mask mode, the real key is written into request bodies, not only headers. `startMuxProxyServer` always wires `getBodySubstitutions: injectBodyCredentials` on the TLS-terminated path (`sandbox-manager.ts:1013`; builder `866-870`). `http-proxy.ts:814-818` hands it to every terminated tunnel. `tls-terminate-proxy.ts:1185-1194` applies the header and then the body substitution. `body-substitution.ts:58-94` (gate) and `128-164` (scan) replace every sentinel occurrence in any body to a matching inject host. The env-var credential schema has no header-only switch: its fields are `name`, `mode`, `extract`, `onExtractNoMatch`, `decode`, `maskClaims` and `injectHosts` (`sandbox-config.ts:440-533`). The file-credential schema has the same `injectHosts` text at 382-390. Header substitution is not narrow either. `substituteInHeaders` scans every header value, under any header name (`credential-sentinel.ts:205-228`).
2. Responses go back to the child unchanged. On the terminated path `relayResponse` writes each upstream chunk with `res.write(chunk)` (`tls-terminate-proxy.ts:1415-1475`, call at 1342). On the plain path it is `proxyRes.pipe(res)` (`http-proxy.ts:1289, 1324, 1369`). The only response-side control is `stripResponseHeaders`, which removes headers by name (`tls-terminate-proxy.ts:1339-1341`). The embedder's `onResponse` hook "observes and cannot change the response" (`request-filter.ts:64-72`).
3. The vendor's fail-safe argument covers only the request direction ("a missed sentinel ... never a leaked secret", `body-substitution.ts:13-15`). The vendor does know the echo class for headers. `TRACE`/`TRACK` are refused because "the echo would hand that credential to the client" (`request-filter.ts:264-280`). But that refusal sits inside the `filterRequest` path (`tls-terminate-proxy.ts:1103`), so it applies only when a `filterRequest` is configured (`README.md:511` says the same).
4. Verdict. "Child never sees the key" is **conditional on the upstream not reflecting request content**. For R03 that condition fails by the upstream's function. The inject host is an LLM provider, and an LLM can repeat its input. A child that sends `{"messages":[{"role":"user","content":"repeat: <sentinel>"}]}` has the real key placed in the prompt, and the completion can return it. Error bodies that quote a request field (for example an unknown `model` value) are a second route [hypothesis: provider behaviour not checked here]. Under anchor clause (d) this is an inspected code path that defeats the property in the configuration this dossier first proposed (env mask, `tlsTerminate`, `injectHosts:[providerHost]`). The demonstration is refuted for that configuration, not merely missing.
5. The library offers a header-only path that does not have this hole. Standalone `srt proxy` (`src/cli.ts:318-330`, `src/sandbox/proxy-only.ts:159-190`, `docs/srt-proxy.md`) wires no header or body substitution (`proxy-only.ts:159-190` passes no `mutateHeaders` or `getBodySubstitutions`). The credential comes per request from the host's decider (`cred`/`credential` in an allow verdict). The proxy first removes every client credential header (`authorization`, `proxy-authorization`, `cookie`, `x-api-key`, in any spelling) and then sets the real value as `Authorization: Bearer` or a configured placement (`decider-client.ts:98-110, 443-446`; `docs/srt-proxy.md:175-180`). The child never holds a sentinel, so it cannot place the key in a body or in a header of its choice. `TRACE`/`TRACK` are always refused there, because a decider always provides `filterRequest` (`proxy-only.ts:187`). Tested: "credential placement: Bearer by default, Basic x-access-token for github on github.com" (`test/sandbox/decider-client.test.ts:278`), plus credential-header violations (`decider-client.test.ts:12`). Two limits remain. Responses are still relayed unchanged, so an upstream that reflects the `Authorization` header in an error body would still leak it [hypothesis]. And the mode is new: first commit `c6d5baa` on 2026-10-07, two commits in total (`git log -- src/sandbox/proxy-only.ts src/sandbox/decider-client.ts`).
6. What the Resonant wrapper must add, in order of preference:
   - (i) Use header-only injection: standalone `srt proxy` with a Resonant decider in a separate broker process, not env-mask mode (also answers S-2).
   - (ii) If env-mask mode is kept anyway, add a `filterRequest` that denies any request to an inject host whose body, query or any header other than `Authorization` contains a registered sentinel. The body is available to the callback as a tee of the pre-substitution bytes (`request-filter.ts:76-91, 231-262`), and the sentinels can be read with `SandboxManager.getSentinelRegistry().entries()` (`sandbox-manager.ts:3525, 3571`; used that way in `credential-mask.test.ts:571-573`). The same callback turns on the `TRACE` refusal. The cost is that the body must be read before the request goes out.
   - (iii) In both cases, scrub responses: replace the real key (and its base64 and URL-encoded forms) in every response header and body chunk before it reaches the child. srt has no hook for this (point 2), so it needs a Resonant-owned relay between the proxy and the child, or an upstream feature request [hypothesis: not designed here].
   - (iv) Acceptance step (h) in section 11.

How the CVE fix is tested [inspected]. Before the fix, `needsNetworkRestriction` was derived from `allowedDomains.length > 0`, so an empty list meant no restriction. Fix `bea2930c` split this into `needsNetworkRestriction = (allowedDomains !== undefined)` and `needsNetworkProxy`. HEAD keeps the same rule at `sandbox-manager.ts:2626-2643`. The fix added `describe('empty allowedDomains network blocking (CVE fix)')` with Linux and macOS cases (`test/sandbox/wrap-with-sandbox.test.ts:557`), which check that the generated bwrap args or Seatbelt profile restrict network. It also added Linux end-to-end cases that run curl, wget and DNS lookups and assert failure (`integration.test.ts:993-1147`, including "Contrast: empty vs undefined network config" at 1199). Two gaps remain. The end-to-end cases are Linux-only; macOS is covered at profile level. And the same bug class survives where `allowedDomains` is absent: `initialize()` does not validate the config (only `config-loader.ts:20, 78` calls `SandboxRuntimeConfigSchema.safeParse`), so a JavaScript embedder that omits `network.allowedDomains` gets `(allow network*)` on macOS and no `--unshare-net` on Linux. The TypeScript type and the zod schema both require the field (`sandbox-config.ts:677-683`). Windows is unaffected because its fence is unconditional.

## 6. Reuse decision

Decision: wrap/adapter. Use it as an npm dependency on Linux and macOS behind a ResonantOS isolation adapter. On Windows, ship it as opt-in "alpha confinement" requiring the one-time elevated install, and keep reporting `contract-only` (unconfined) when the install is absent or declined. Do not adopt it as the sole Windows answer until the anonymous-token residual and the python.exe piped-stdio case are measured (section 11). For R02 it beats the alternatives in section 12, because it is the only candidate with containment tests on all three OSes in one Node library.

R03 (amended 2026-10-21 after S-1, which is accepted). The decision changes from "env masking in the bridge" to **conditional wrap**, with two changes:
- Do not use env-mask mode toward an LLM provider. Its body substitution plus unscrubbed responses lets the child obtain the key (section 5, "Secret reflection").
- If srt brokers R03 at all, it does so through the header-only standalone `srt proxy`. That proxy runs in a separate low-privilege broker process (S-2) with a Resonant decider that supplies the credential per request. The Resonant layer adds response scrubbing of the real key (section 5, point 6).
The R03 claim is "not demonstrated" until acceptance step (h) passes. Confidence for R03 is low: the standalone mode is two weeks old, and the way it would be wired to the containment's proxy relay has not been established (section 14). Whether the srt-proxy broker or a reimplemented broker (aegis pattern) serves R03 is a lead decision.

## 7. Integration design

Process boundary (amended 2026-10-21, S-2 accepted): do not run srt's proxies in the bridge process. They parse bytes from an adversarial child (HTTP, SOCKS via the single-author `@pondwader/socks5-server`, TLS via node-forge). In the bridge, a parser bug would become access to the keys (A1) and the bridge tokens (A2), not just a sandbox escape. Design constraint:
- A separate low-privilege Node helper ("isolation broker") imports the library, calls `SandboxManager.initialize()` and spawns the delegated children.
- For R03, a standalone `srt proxy` in that helper or a third process gets the provider credential per request from a decider over an inherited fd (`docs/srt-proxy.md:1-40`). That process holds provider keys only, never bridge tokens.
- `SandboxManager` can be pointed at an external proxy through `network.httpProxyPort`/`socksProxyPort` ("the external proxy must handle domain filtering", `sandbox-config.ts:760-777`).
- `srt proxy` with `--listen` on loopback TCP has no authentication (`docs/srt-proxy.md`, `--listen` row). Prefer `--listen-fd` on a Unix socket in a host-only directory. Whether `httpProxyPort` can target such a socket, or whether the decider can tell the child's requests from another local process's, is not established (section 14) [hypothesis].
- The bridge reaches the helper over an inherited pipe, never over its main loopback listener (X-5). Node 24 meets `engines >=22.12` and reads `NODE_USE_ENV_PROXY`, which is set on Windows (`README.md:1066`).

Alpha files that change:
1. New `browser-first/host/delegation-isolation-srt.mjs` implementing the same adapter shape as `createDelegationIsolationAdapter` (`delegation-isolation.mjs:393-457`). `resolve()` returns `{mode: "srt-linux"|"srt-macos"|"srt-windows"|"contract-only", reason, warnings}`. `checkDependencies().warnings` and Windows fence residuals go into `reason`/`warnings` and the governance audit.
2. `host/delegation-isolation.mjs:47-69`: dispatch to the srt adapter when `RESONANTOS_DELEGATION_ISOLATION=srt`. The existing values and the default stay unchanged in the first PR.
3. `host/addon-delegation-service.mjs`: `wrapCommandForIsolation` becomes async at the call sites 1696 and 2271, because srt wraps are promises. On Windows `wrapWithSandboxArgv` returns `{argv, env}` and the caller must spawn `argv` with `shell:false` and that env. The child env on Windows is not the caller's env: only `PATH`, `PATHEXT`, credential sentinels, proxy and git variables reach it (`windows-sandbox-utils.ts:4250-4262`). Hermes's `HERMES_HOME` and related variables would have to travel in the command text (`cmd /d /s /c "set ...&& python ..."`) [hypothesis: workable, not tested].
4. Keys (R03), amended 2026-10-21. Remove the `OPENAI_API_KEY`/`RESONANTOS_HERMES_API_KEY` injection (1776-1779) and the `providerEnvFromSecrets` merges (1625, 2247). Give the child a fixed non-secret placeholder key, so the provider SDK starts. The broker's decider answers each allowed request to the provider host with `cred`/`credential`. The proxy strips every client credential header and places the real key (`decider-client.ts:98-110, 443-446`). Do not use `credentials.envVars` `mode:"mask"` toward a provider (S-1). If env-mask mode is used anyway for some non-echoing host:
   - (a) `injectHosts` must be mandatory. If it is omitted, the key is injected "at every reachable host" (`sandbox-config.ts:524-532`), so a child could post the sentinel to any allow-listed host it can read back from (S-4). The adapter rejects a mask entry without `injectHosts` and has a unit test for it.
   - (b) A Resonant `filterRequest` denies sentinels outside the `Authorization` header (section 5, point 6 (ii)).
   - (c) The masking reads the real value from the embedding process's own `process.env` (`sandbox-manager.ts:1774-1778`). So every unsandboxed spawn with the full `process.env` must be closed first: `opencode serve` at `opencode-client.mjs:281-285` (OSC-34).
   Validate the config with `SandboxRuntimeConfigSchema.parse()` before `initialize()` (section 5 gap).
5. Reads, amended 2026-10-21 (S-3 accepted). The Alpha's `readDenyRootsFor` (`delegation-isolation.mjs:175-209`) is macOS-shaped. It has no Linux `~/.config/google-chrome`, `~/.config/chromium`, `~/.config/BraveSoftware`, `~/.mozilla`, and no Windows `%LOCALAPPDATA%\Google\Chrome\User Data`. Among user state it denies only `ResonantOS_User/Secrets`. Reads are open by default, so reusing that list would leave the browser profile, with the extension's token copies (OSC-06) and cookies (A4), and the rest of `~/ResonantOS_User` (A3) readable. Use srt's deny-then-allow layering instead: `denyRead: [<home>]` plus `allowRead: [<delegation workspace>, <toolchain dirs>]`. `allowRead` "takes precedence over denyRead" (`sandbox-config.ts:972-978`; tests in `test/sandbox/allow-read.test.ts`, names read, not run). If a deny list is kept, it must be per-OS and include the browser profiles and `~/ResonantOS_User` outside the workspace.

Break points:
- DSH and `opencode serve` run servers on 127.0.0.1 that the bridge connects to (`dsh-runtime.mjs:285`). Under Linux `--unshare-net` the sandbox has its own loopback (`README.md:990`), so the bridge cannot reach a server inside it. Those runtimes need a Unix-socket transport or must stay on the CLI path [inspected for the network design; impact on DSH is a hypothesis].
- Hermes over Python `httpx` needs the MITM trust bundle (`SSL_CERT_FILE` and related, `tls-terminate-trust-env.test.ts`).

Alpha tests affected (of the 2,424): `test/delegation-isolation.test.mjs:80-112` (the platform matrix asserts `contract-only` for linux and win32, unchanged while the default stays put); `test/delegation-isolation-live.test.mjs` (macOS live test, now also needed on Linux and Windows); `test/addon-delegation-service-error-handling.test.mjs` (45 isolation references; async wrap and new modes); `test/opencode-execution-revocation.test.mjs`; `test/delegation-bridge-inprocess-self-test.test.mjs` and `test/browser-first-acceptance.test.mjs` (deterministic adapter, unaffected unless defaults change). Any test that asserts the child env contains a provider key would have to assert the sentinel instead [hypothesis: I did not grep every test for this].

Error behaviour: map `initialize()` rejections (`WindowsSandboxError.code`, `LinuxSandboxProfileError.code`) to `contract-only` with a reason and require explicit user consent to continue, keeping the Alpha's current governance-audit behaviour (`delegation-isolation.mjs:65`).

## 8. Security and governance effects

- New privileges: on Windows, an admin-installed local account, machine-wide WFP filters, an HKLM DPAPI credential and a CA in `%ProgramData%`. By default the install also makes the installing user's profile readable to every sandboxed command of every local user, except credential stores (`README.md:754, 825-861, 936-940`). For ResonantOS the install should use `--skip-profile-grant`.
- Windows CA key (added 2026-10-21, S-5 accepted). The TLS-termination CA private key sits in `%ProgramData%\sandbox-runtime\ca\`. That directory is ACL'd so that "Administrators own it, BUILTIN\Users have modify, and the sandbox group carries an explicit `(OI)(CI)` DENY" (`windows-sandbox-utils.ts:1852-1863`, a code doc comment [reported in code]). Trust is "ADDITIVE": a rotation adds the new cert and earlier ones stay trusted (`windows-sandbox-utils.ts:1998-2004`). Sandboxed children cannot read it, but every other local account can read or replace the key that terminated-TLS trust rests on. That matters on shared or lab machines, such as shared field laptops. I found no per-user CA option (not searched exhaustively). The Windows opt-in UX must say this.
- Silently permissive, or visible only if the embedder asks:
  - Linux without `apply-seccomp` (unsupported architecture or a custom path): AF_UNIX and namespace limits are off. The only signals are a warning and a debug log (`linux-sandbox-utils.ts:1329-1334, 3624-3629`). An old helper "imposes no limit, and nothing says so" (`README.md:718`).
  - `enableWeakerNestedSandbox` combined with `allowAllUnixSockets` leaves the user-namespace limit off (`README.md:717`).
  - Credential masks fail open by default (above).
  - Env-mask mode substitutes the real key into request bodies and any header to an inject host, and relays responses unscrubbed. An echoing inject host returns the key to the child (S-1, section 5). Nothing warns about this.
  - On Windows, the anonymous-token and derived-token connects, ICMP, SMB, WSL and DNS are not fenced (`README.md:1007-1010`; `winsrt.test.ts:5236`).
  - On macOS, `allowLocalBinding` opens every loopback port; `allowAppleEvents` removes code-execution isolation (`README.md:1280`).
  - Bubblewrap version is not checked against known advisories.
- Attack surface: TLS termination and HTTP/SOCKS parsers of child-controlled bytes, plus node-forge for the CA. If embedded in the bridge, these sit next to A1 and A2 (S-2, X-6). Section 7 now moves them to a separate broker process. The proxy auth token is visible on the Windows runner's command line to same-session principals (`README.md:1006`).
- Revocation: `updateConfig()` changes allowlists live, `reset()` tears down, and killing the broker kills the Windows child. There is no per-child revocation beyond process kill.
- Trust in the maintainers: a single vendor (Anthropic) with fast releases and thin issue triage. Binary helpers are built in CI with npm provenance.
- User friction: Windows needs one UAC prompt per machine and per upgrade (setup-version bumps force a re-install, `README.md:762`). Schannel tools (System32 curl, PowerShell web cmdlets, .NET HttpClient, winget) do not work inside the Windows sandbox (`README.md:799-807`). Ubuntu 24.04 users must relax an AppArmor sysctl or add a profile (`README.md:701-707`).
- Windows 0xC0000142 question (yzyyohh/dsh-windows-sandbox-0xc0000142: restricted-token children with piped stdio fail with `DLL_INIT_FAILED`). The measurement drove DSH's own ACL backend, not srt. srt-win is built around exactly this failure. The broker creates an isolated desktop and grants `srt-sandbox` on `WinSta0`, and the code comment records that the child "DLL_INIT_FAILED without it" (`winsta.rs:19-24`). It also grants create rights on the session `BaseNamedObjects` for msys2/cygwin (36-49). Std handles are passed explicitly with `STARTF_USESTDHANDLES` and a handle list, which avoids conhost allocation under the restricted token (`launch.rs:229-257`). The sandbox side holds only pipe client ends (`logon.rs:12-15`). CI row D starts `cmd.exe`, Windows PowerShell and `node` under the write-restricted token with redirected (piped) stdout and stderr (`smoke-write-restricted.ps1:95-110, 409-453`). H2 pipes stdout through the two hops (`winsrt.test.ts:4660`). So the counterexample is refuted by design and CI for cmd, powershell and node [inspected, not executed]. python.exe and git.exe are not in the CI rows, so the Hermes case (Python, piped stdio) remains open.

## 11. Acceptance test (a request for the user, not a plan)

Requires executing third-party code, so each run needs approval: install `@anthropic-ai/sandbox-runtime@0.0.81` into a throwaway project outside the research tree, run on a disposable VM per OS, and on Windows run `windows-install --skip-profile-grant` once (UAC).

Child (python.exe on every OS, with stdio piped exactly as at `addon-delegation-service.mjs:1705`) attempts:
- (a) print `OPENAI_API_KEY`;
- (b) read the secret file;
- (b2) read the Chrome profile LevelDB for the ResonantOS extension ID (per-OS profile path) (added, S-3);
- (b3) read `~/ResonantOS_User/HUMAN_KNOWLEDGE` (added, S-3);

- (d) connect to `127.0.0.1:<P>`;

## 12. Recommendation and confidence

Benefits: one Node library covers all three OSes with deny-by-default network and write. The test suite is large and adversarial in style, with CI on six legs plus Docker. The Windows design takes the restricted-token, desktop and stdio failure modes seriously. Amended 2026-10-21: it does not by itself close T2. Its env masking keeps the key out of the child's environment, but an echoing provider can return it (S-1). Its header-only `srt proxy` mode is the usable broker building block, and it still needs a Resonant decider, response scrubbing and a separate process.

Trade-offs and blockers:
- Windows needs admin, runs as a separate account, carries known residuals against adversarial code, and breaks Schannel tools.
- Module-singleton config means one sandbox session per bridge process.
- Loopback servers inside the Linux netns are unreachable from the bridge (DSH, `opencode serve`).
- Reads are open by default. Use deny-home plus `allowRead`, not the Alpha's macOS-shaped list (S-3).
- Issue triage is thin.
- Blocker S-1 (accepted). Env-mask mode leaks the key through an echoing inject host. R03 via srt is conditional on the header-only `srt proxy` mode, a Resonant response scrubber, and acceptance step (h) passing.
- The proxies must not run in the bridge process (S-2). The broker transport must be agreed with R05 (X-5).

Readiness: Linux and macOS are ready behind a flag. Windows is alpha.

Evidence quality: about 75% [inspected] (code, tests, CI files, fix commit), about 25% [reported] (README residual descriptions, advisory, production use). Nothing [executed]. Rough proportions, not counted. After A-2 the Windows WFP and ACL sentences cite `wfp.rs`/`acl.rs`. The CA ACL (S-5) rests on a code doc comment and is labelled [reported in code].
