Scope: the selected path (A1 now, A2 by seams, A3 for the DAO; `architecture/reference-architectures.md` section 5). Each row names the threat ids from `ledger/threat-model-draft.md` v0.2.1, the layer that owns the guardrail (core, adapter, user confirmation, off-chain reviewer, on-chain contract: the master prompt's five placements), the mitigation in the selected path, the residual the article must state, and the acceptance test that would change the row (`architecture/acceptance-backlog.md`). Likelihood and impact are the lead's judgement (H, M, L). Every mitigation is designed, not yet tested, unless marked "upstream test".

## 3. Five serious negative findings (master prompt Stage 3 deliverable), carried into the article

1. The top-ranked containment candidate's credential masking returns the key to a child through an echoing provider (S-anthropics-sandbox-runtime-1, blocker, accepted; settled from `body-substitution.ts:58-94, 128-164` and `tls-terminate-proxy.ts:1415-1475`).
2. No shortlisted codebase supplies an adoptable R22 credential; the "audited NonTransferable Points" pattern lives only on an unmerged branch whose `TransferPoints` moves tokens anyway (rewards dossier headline, D-1).
3. The shared Realms instance every DAO would inherit runs code with no public source (3.1.7 versus 3.1.3) under a 5-of-7 council with hold-up 0 and no veto; governance CI failed 31 of 31 runs (realms dossier headlines 1-2).
4. Every R11 design (tessera, hypercore, durabletask, datalad) keeps the key beside the ledger and so detects accidents, not same-user tamper (X-2); hypercore's only equivocation test has been skipped for 20 months and its writes are not fsynced.
5. Ten dossiers placed security state where the adversary they defend against can write it (X-1), and seven ended their approval design in the agent's own context (X-4); the fixes are substrate decisions, not per-component patches.
